Meet

Meeting API

For another website, such as a booking or tutoring site, to create video meetings and give each person their own join link.

The idea

  1. When a lesson is booked, your server creates a meeting, passing your own lesson id as externalId.
  2. It asks for a join link for each person: the tutor as "host", the student as "guest". Each link opens the meeting with that person's name already filled in. Nobody needs an account here.
  3. It shows the meeting inside its own lesson page with the iframe that comes with each link, so nobody leaves your site.
  4. If the lesson moves, update the meeting. If it's cancelled, delete it. Links already sent keep working for the new time.

The room opens 15 minutes before the start and closes an hour after the end. People with a host link can go in any time. Hosts can allow or stop each person's mic, camera, screen share and chat during the call.

Keys

The account owner creates a key on their dashboard (API keys). Send it with every request:

Authorization: Bearer mk_...
  • Server-to-server only. Keep the key in your server's secrets, never in web page or app code. Requests from another site's browser are refused.
  • The API is part of the paid host account: every request needs the key's account to have an active host subscription (otherwise 402). Meetings made through it belong to that account.
  • Limit: 120 requests a minute per key (429 with Retry-After).
  • Deleting a key on the dashboard stops it straight away.

Base address: https://meet.example.com/api/v1. Bodies are JSON (Content-Type: application/json). Times are ISO 8601 in UTC, e.g. "2026-11-20T16:00:00Z".

Endpoints

RequestWhat it does
GET/accountCheck the key works: the account's name and whether it can host.
POST/meetingsCreate a meeting.
GET/meetingsList upcoming meetings (?from=, ?to=, ?limit= up to 200), or find one with ?externalId=.
GET/meetings/{id}One meeting.
PATCH/meetings/{id}Change title, startsAt, durationMin or timezone.
DELETE/meetings/{id}Cancel it. Its link and all join links stop working.
POST/meetings/{id}/linksA personal join link for one person.

Create a meeting

curl -X POST https://meet.example.com/api/v1/meetings \
  -H "Authorization: Bearer $MEET_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Maths with Ms Patel",
    "startsAt": "2026-11-20T16:00:00Z",
    "durationMin": 60,
    "timezone": "Europe/London",
    "externalId": "lesson-1042"
  }'
Field
startsAtRequired. Within the next year.
durationMin15 to 480. Default 60.
titleUp to 100 characters. Default "Meeting".
timezoneIANA name, used to word invitation emails. Default "UTC".
externalIdOptional, recommended: your own id (letters, digits, . _ : -). Sending the same one again returns the existing meeting ("created": false) instead of making another, so retries are safe.
invitees, noteOptional. Up to 10 email addresses that this site emails an invitation to (needs the account's email confirmed; 30 a day). Leave out if your site sends its own emails.

Answer (201, or 200 for an existing externalId):

{
  "data": {
    "id": "k3m9xq2vbn7d",
    "url": "https://meet.example.com/m/k3m9xq2vbn7d",
    "title": "Maths with Ms Patel",
    "startsAt": "2026-11-20T16:00:00.000Z",
    "durationMin": 60,
    "timezone": "Europe/London",
    "externalId": "lesson-1042",
    "status": "upcoming",
    "createdAt": "2026-11-06T10:12:00.000Z"
  },
  "created": true,
  "invited": 0
}

status is "upcoming", "open" (from 15 minutes before) or "ended". url is the plain meeting link: anyone with it can join as a guest and type their own name.

Personal join links

curl -X POST https://meet.example.com/api/v1/meetings/k3m9xq2vbn7d/links \
  -H "Authorization: Bearer $MEET_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "Ms Patel", "role": "host" }'
{
  "data": {
    "url": "https://meet.example.com/m/k3m9xq2vbn7d?link=eyJyb29tIj...",
    "embedUrl": "https://meet.example.com/m/k3m9xq2vbn7d?link=eyJyb29tIj...&embed=1",
    "iframe": "<iframe src=\"...\" allow=\"camera; microphone; display-capture; autoplay; fullscreen\" ...></iframe>",
    "embedAllowedOn": ["https://tutoring.example.com"],
    "name": "Ms Patel",
    "role": "host",
    "expiresAt": "2027-02-04T10:12:00.000Z"
  }
}

url opens the meeting on this site. embedUrl and iframe are for showing it inside your own page (see below).

  • name: required, up to 40 characters. Shown to everyone in the call, and can't be changed by the person.
  • role: "host" (can enter early, and controls who may use their mic, camera, screen share and chat) or "guest" (default).
  • expiresInDays: 1 to 365, default 90.
  • Make links when you need them; there's no limit and nothing is stored. Treat each link like a password for that meeting: send it only to that person. To stop all of a meeting's links, delete the meeting.

Inside your own page

To keep people on your site, put the meeting in an iframe instead of linking to it.

  1. Allow your site once. The account owner adds your site's address (e.g. https://tutoring.example.com) under Websites that can show your meetings on the dashboard. Browsers refuse to show the meeting on any site that isn't listed. embedAllowedOn in the link answer (and in GET /account) shows the current list.
  2. Put the iframe from the link answer in the person's lesson page. It includes the allow list the meeting needs for the camera, microphone and screen sharing; if you write your own iframe, keep that allow attribute. Change the size to suit your page (at least about 360×480).
<iframe src="https://meet.example.com/m/k3m9xq2vbn7d?link=eyJyb29tIj...&amp;embed=1"
        allow="camera; microphone; display-capture; autoplay; fullscreen" allowfullscreen
        style="width:100%;height:640px;border:0;border-radius:12px" title="Video meeting"></iframe>

Use a personal join link in the iframe (not the plain meeting url): browsers don't send logins into iframes, so the link is what makes the tutor the host and fills in each name.

Events from the meeting

The meeting tells your page what's happening with postMessage (only to the sites on the allowed list):

window.addEventListener("message", (e) => {
  if (e.origin !== "https://meet.example.com" || e.data?.source !== "meet") return;
  switch (e.data.event) {
    case "ready":    /* lobby showing: { title, isHost } */ break;
    case "not_open": /* { status: "early" | "over" | "unavailable", startsAt } */ break;
    case "joined":   /* they're in the call: { name, isHost } */ break;
    case "people":   /* { count } people in the call */ break;
    case "left":     /* they pressed Leave */ break;
    case "ended":    /* call ended for them: { reason } */ break;
  }
});

Every message also has meeting (the meeting id).

Reschedule or cancel

curl -X PATCH https://meet.example.com/api/v1/meetings/k3m9xq2vbn7d \
  -H "Authorization: Bearer $MEET_API_KEY" -H "Content-Type: application/json" \
  -d '{ "startsAt": "2026-11-21T16:00:00Z" }'

curl -X DELETE https://meet.example.com/api/v1/meetings/k3m9xq2vbn7d \
  -H "Authorization: Bearer $MEET_API_KEY"

Example: Node.js / Cloudflare Workers

const MEET = "https://meet.example.com/api/v1";

async function meet(path, method = "GET", body) {
  const res = await fetch(MEET + path, {
    method,
    headers: { Authorization: `Bearer ${process.env.MEET_API_KEY}`, "Content-Type": "application/json" },
    body: body ? JSON.stringify(body) : undefined,
  });
  const json = await res.json();
  if (!res.ok) throw new Error(`${json.error.code}: ${json.error.message}`);
  return json.data;
}

// When a lesson is booked:
const m = await meet("/meetings", "POST", {
  title: `${lesson.subject} with ${tutor.name}`,
  startsAt: lesson.start.toISOString(),
  durationMin: lesson.minutes,
  externalId: `lesson-${lesson.id}`,
});
const tutorLink = (await meet(`/meetings/${m.id}/links`, "POST", { name: tutor.name, role: "host" })).url;
const studentLink = (await meet(`/meetings/${m.id}/links`, "POST", { name: student.name })).url;
// Save m.id with the lesson, and put each link in that person's lesson page or email.

Errors

{ "error": { "code": "invalid_starts_at", "message": "startsAt must be in the next year." } }
StatusMeaning
400Something in the request isn't valid. code says which field.
401Missing or wrong API key.
402The account's host subscription isn't active (needed for every request).
403Called from a browser on another site, or email not confirmed (for invitees).
404No such meeting on this account.
415The body must be JSON.
429Too many requests (or the daily invitation limit).

If both sites run on Cloudflare Workers in the same account, a service binding can call these same addresses without going over the internet. The key is still needed.
